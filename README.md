# Коми сёрни чукӧртысь бот

VK-бот FU-Lab для сбора голосовых записей на коми языке. Участник выбирает район, даёт согласие и читает предложенные фразы. Веб-панели позволяют проверять записи и загружать новые тексты. Обучение ASR/TTS выполняется отдельно.

## Что входит

- Приём голосовых, случайная выдача доступных фраз, резервирование и защита от повторных событий.
- «Водзӧ» пропускает фразу. «Бӧр» в основном меню отменяет последнюю запись и возвращает её текст, если он доступен для повторной записи. Сообщение в VK и файл на диске остаются; запись исключается из одобренного экспорта.
- «Вежны подув юӧр» меняет район. В этом меню «Бӧр» возвращает к записи.
- `/start`, `/skip`, `/region`, `/undo`, `/help` остаются текстовыми командами.
- `/vk_bot/admin/index.php` — модерация; `/vk_bot/admin/phrases.php` — импорт и редактирование фраз.
- `/vk_bot/admin/export.php` — CSV одобренных записей. Аудиофайлы передаются отдельно.

Стек: PHP 8.3 + Apache в Docker, MariaDB 11.4, внешний HTTPS reverse proxy. Рабочий код перенесён из снимка сервера от 12 октября 2026 года. Конфигурация окружения задаётся отдельно.

## Новая установка с пустой базой

Требуются Docker Engine с Compose, Git и настроенный HTTPS-домен. Для приватного репозитория нужен доступ GitHub; не записывайте токены в URL команд.

```bash
git clone https://github.com/VojvyvKiro/komi-voice-bot.git
cd komi-voice-bot
cp compose.example.yaml compose.yaml
cp config.example.php config.php
cp env.example .env
id -u
id -g
```

В `.env` замените все `REPLACE...`, укажите `LOCAL_UID`/`LOCAL_GID` по выводу `id` (обычный пользователь, не root). `DB_PASSWORD`, `DB_ROOT_PASSWORD`, `ADMIN_PASSWORD` должны быть разными. `VK_TOKEN` — токен сообщества с доступом к сообщениям; `VK_SECRET_KEY` и `VK_CONFIRMATION_CODE` должны соответствовать настройкам подключаемого сервера Callback API. `BASE_URL` — внешний адрес сайта. PHP читает переменные окружения, а Compose передаёт их из `.env`.

```bash
chmod 600 .env
mkdir -p uploads/recordings
touch bot.log
chmod 755 uploads uploads/recordings
chmod 644 config.php bot.log
docker compose build web
docker compose up -d --wait db
```

**Следующая команда только для новой пустой БД. При переносе существующего бота используйте [MIGRATION.md](MIGRATION.md).**

```bash
docker compose exec -T db sh -c 'exec mariadb -u"$MARIADB_USER" -p"$MARIADB_PASSWORD" "$MARIADB_DATABASE"' < schema.sql
docker compose run --rm --no-deps web php tools/migrate.php
docker compose run --rm --no-deps web php tools/migrate-phrases.php
docker compose up -d web
```

`schema.sql` создаёт базовые таблицы без текстового корпуса. Обе миграции обязательны. Первая миграция при первом применении устанавливает активным фразам квоту 1, оставляя отключённые фразы отключёнными. Повторное применение отмеченной миграции ничего не меняет. Исторические демонстрационные фразы лежат отдельно в `examples/` и автоматически не загружаются.

Веб-контейнер слушает только `127.0.0.1:8085`. Для nginx на том же хосте внутри уже настроенного HTTPS `server`:

```nginx
location /vk_bot/ {
    proxy_pass http://127.0.0.1:8085;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 2m;
    proxy_read_timeout 120s;
}
```

У `proxy_pass` нет завершающего `/`: путь `/vk_bot/` сохраняется. TLS-сертификат и домен настраиваются на стороне reverse proxy. Для proxy в другом контейнере `127.0.0.1` обозначает сам контейнер, поэтому потребуется отдельная сетевая конфигурация.

## Подключение VK и проверка

В настройках Callback API сообщества укажите внешний `https://ВАШ-ДОМЕН/vk_bot/callback.php`, согласованный секретный ключ и код подтверждения в `.env`. После изменения `.env` выполните `docker compose up -d --force-recreate web`, чтобы контейнер получил новые значения. Включите событие новых сообщений. Код также принимает `message_allow` и `message_deny`.

Локальная диагностика:

```bash
curl -i http://127.0.0.1:8085/vk_bot/admin/index.php
curl -i http://127.0.0.1:8085/vk_bot/callback.php
docker compose ps
docker compose logs --tail=50 web
```

Без авторизации панель отвечает 401; Callback без JSON — 400. Корень `/` отвечает 403 намеренно. Не открывайте весь каталог Apache: конфиги, логи и внутренние PHP-файлы должны оставаться недоступны из интернета.

После подключения проверьте `/start`, район и согласие, выдачу текста, отправку аудио, «Бӧр» и повторную запись, «Водзӧ», панель модерации и CSV. Проверку нового сервера до переноса лучше проводить через отдельное тестовое сообщество. Для рабочего сообщества порядок переключения описан в MIGRATION.md.

## Тексты и записи

В панели фраз загрузите TXT UTF-8: одна готовая коми фраза на строку. `phrases.txt` не входит в программу и не нужен для запуска: это произвольное имя входного корпуса. Русский или параллельный перевод не требуется. Сначала выполняется проверка файла, затем оператор подтверждает добавление. Максимум файла — 128 МиБ; браузер отправляет его частями по 512 КиБ, поэтому не нужно разрешать HTTP-запрос на 128 МиБ.

Пустые строки, точные повторы и невалидные строки не добавляются. Лимит отдельной строки в панели — 3000 символов. Редактирование создаёт новую фразу и отключает прежнюю, сохраняя исходный текст старых записей. Незавершённый импорт можно продолжить в панели.

CLI-импорт предназначен для небольших файлов: он загружает исходный файл и существующие тексты в память. Для большого корпуса используйте веб-панель с порционной обработкой.

По умолчанию одна незабракованная запись закрывает квоту фразы. `uploaded` уже учитывается, ожидание модерации не вызывает повторную выдачу. Резерв фразы действует 24 часа. Отказ от записи/модерация не удаляют физические аудиофайлы.

Аудио лежат в `uploads/recordings/{speaker_id}/`, а связь с текстом, участником и статусом — в MariaDB. `uploads/phrase-imports/` содержит временные файлы импорта. CSV — только таблица метаданных; для обучения нужен также набор соответствующих аудиофайлов. Экспорт содержит идентификаторы участников, передавайте его согласованным получателям.

Диапазон длительности задаётся в `config.php` через `MIN_DURATION_SEC` и `MAX_DURATION_SEC` (пример: 1–60 секунд). Это ограничение приёма бота, а не требование модели ASR/TTS.

## Обновление

Делайте резервную копию БД и `uploads` перед изменениями; порядок и команды — в MIGRATION.md. Сначала остановите web, затем обновляйте код, собирайте образ и запускайте миграции. Не заменяйте `.env`, `config.php` и рабочий `compose.yaml` шаблонами. Сравнивайте изменения шаблонов отдельно.

```bash
docker compose stop web
git pull --ff-only
docker compose build web
docker compose run --rm --no-deps web php tools/migrate.php
docker compose run --rm --no-deps web php tools/migrate-phrases.php
docker compose up -d web
```

При ошибке не продолжайте переключение: сохраните вывод и восстановите согласованную копию кода, БД и файлов. `docker compose down -v` удаляет том БД — для обновления он не нужен.

## Проверки и ограничения

GitHub Actions проверяет синтаксис PHP в образе из Dockerfile. Это не интеграционный тест VK/MariaDB и не нагрузочный тест. Снимок содержит работающий на исходном сервере код; перенос на новый сервер требует описанной проверки.

Выбор фраз использует `ORDER BY RAND()` и блокировки очереди. Пропускная способность на сотнях тысяч фраз не измерена; после массового импорта проверяйте задержки, CPU/RAM и логи. Заданные в Compose лимиты памяти — стартовая конфигурация, а не гарантия под любую нагрузку.

Секреты, аудио, логи, корпус и дампы не входят в Git. Репозиторий содержит код и схему, но не текущую рабочую базу.
